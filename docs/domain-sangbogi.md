# 상차림 도메인 로직 — 현황과 개선 계획

이 문서는 초하루/명절 상차림 로직의 **현재 동작**, **문제점**, **확정된 요구사항**,
**아직 정해야 할 것**을 담는다. 코드를 고치기 전 반드시 이 문서를 읽고, 고친 뒤 갱신한다.

---

## 1. 현재 동작 (as-is)

### 대체(substitute) 개념
- 각 음력 달에 "초하루를 대신하는 날"이 `SUBSTITUTES`에 정의돼 있다.
- `substituteFor(e)`: 그 달에 대체일이 있으면 그 명절 객체를 반환.
- `sangDate(e)`: 대체일이 있으면 상 올리는 날을 **명절 날짜로 덮어씀** (초하루 날짜 버림).
- `cycleKey(e)`: 저장 키가 한 달에 **하나**뿐 (`sangbogi:cycle:<연>-<월>`).
- `doneKey(e)`: 완료 표시가 `done:추석` **또는** `done:초하루` 중 하나.
- `renderSang()`: 품목 목록이 명절/초하루 구분 없이 **항상 동일**(FIXED+VARI).
- `STEPS`: 상 올린 뒤 절차도 명절/초하루 **동일한 6단계**.
- 화면 안내 문구: "이 날 상을 올리고 초하루 상은 생략합니다."

## 2. 문제점 (why it's wrong)

핵심: **"명절이 들면 무조건 초하루를 건너뛴다"는 전제가 틀렸다.**

- 실제로는 초하루를 명절로 **대신해도 되는 달**과 **대신하면 안 되는 달**이 나뉜다.
- 초하루는 한 달을 여는 별개의 법도라, 원칙적으로 매달 챙겨야 한다.
- 명절(특히 추석)은 차례를 지내며, 그때 신당에서 하는 일이 초하루와 **전혀 다른데**
  현재는 품목도 절차도 초하루와 똑같이 처리된다.

---

## 3. 확정된 요구사항 (to-be, 사용자 확인 완료)

1. **초하루는 매달 고정으로 항상 뜬다.** 한 달을 여는 별개의 법도.
2. **명절마다 "대체 가능 여부" 속성을 둔다.**
   - **대체 불가**(예: 추석): 초하루도 챙기고 명절도 **반드시 따로** 챙긴다 → 그 달 상이 둘.
   - **대체 가능**(예: 칠석): 은호당의 선택 / 신령님 지시에 따라 매달 정한다.
     대신하기로 하면 초하루를 건너뛰고 그 명절만, 대신 안 하면 둘 다.
3. **명절 상은 초하루 상과 품목·절차(차례)가 다르다.** 명절별로 다른 상차림/절차 필요.
4. **적용 시점: 2027년(내년) 추석부터.** 2026년 추석은 이미 지났으므로 소급하지 않는다.

## 4. 아직 정해야 할 것 (open questions)

### (A) 대체 불가 명절 전체 분류  — **미정**
- 추석 = 대체 불가(확정), 칠석 = 대체 가능(확정).
- 나머지(홍수맥이/영등맞이/삼신날/초파일/단오/백중/중양/성주맞이/동지/삼재풀이)가
  각각 어디에 속하는지 사용자 확인 필요.

### (B) 추석 상의 실제 내용  — **확정** (아래 6절 참고)
- 만연당 선생님(제자에게 법도를 가르치는 분)이 네이버 카페에 올린 글을 근거로 확정.
- 상세는 이 문서 "6. 추석 상·차례 규칙" 절에 정리.

### (C) "대체할지 말지"를 정하는 UI  — **개략 합의**
- 대체 가능한 명절만 매달 토글로 정함. 기존 택일(pick) UI 근처에 배치 가능.
- 구체 방식은 (A)(B) 확정 후 설계.

## 5. 구현 시 데이터 모델 주의
- 지금은 한 달에 저장 키 하나(`sangbogi:cycle:<연>-<월>`).
- 대체 불가 명절이 있는 달은 **초하루 상 + 명절 상 두 벌**을 저장해야 한다.
- 기존 키와 충돌하지 않는 새 키 체계가 필요 (예: 명절 상은 `...:<연>-<월>:<명절명>` 등).
- 기존 저장 기록(Supabase 실데이터)을 깨뜨리지 않도록 마이그레이션/호환을 반드시 고려.
- 작업 순서: **(A)(B) 확정 → 설계안 문서화 → 사용자 승인 → 구현 → 검증 → 문서 갱신.**

## 6. 추석 상·차례 규칙 (확정)

> 출처: 만연당 선생님이 네이버 카페 "애동제자 길라잡이"에 올린 글
> ("추석명절에 많이하는질문 차례상", "만연당의 차례상준비").
> 사용자(은호당 제자)가 배우는 법도이며 내용 정확성을 확인함.
> ※ 아래는 이 신당/법도의 규칙이며 일반적인 추석 차례와 다를 수 있다.

### 6.1 초하루 상과의 핵심 차이
- 추석은 그 달 **초하루 격식을 이미 치른 뒤**라서 **시루를 찌지 않는다**
  (백시루/콩시루/팥시루 없음). 대신 **송편**을 소당·중당·육당 삼당에 올린다.
- 공양: 초하루는 전안 크기에 따라 3/7/9그릇도 올리지만,
  추석엔 소당·중당·육당에 **공양 한 그릇씩 + 토란국 한 그릇씩**.
- 추석에는 초하루엔 없는 **차례상**이 따로 생긴다.

### 6.2 자리별 차림 (전안)
- **소당**: 식혜 또는 수정과 (배 옆 빈 잔이 식혜잔) · 송편 · 공양 · 토란국
- **중당**: 막걸리 삼잔 (감 옆) · 송편 · 공양 · 토란국
- **육당**: 장군님 술잔 "작" · 송편 · 공양 · 토란국

### 6.3 차례상 (추석에만; 초하루엔 없음)
- 굿상 기준. 제자의 신명 기준은 **6공기**
  (일반인 제사는 밥 3공기 + 모듬밥이나, 제자는 양두부리 신명이라 6공기).
- 좌측: **소주 삼잔** / 우측: **막걸리 삼잔** / 양쪽에 **촛대**.
- 신명 순위: 미혼 제자 = 친가·외가 / 기혼(자식 있는) 여성 제자 = 시댁·친가.
  (제사의 우선순위는 신명 순위와 다름 — 여성 기혼 제자는 제사 기준 1순위 시댁, 2순위 친가.)
- **신령님 상이 우선**: 조상만 대접하는 법은 없고, 신령님을 대접하면서 조상을 대접한다.

### 6.4 건립
- **상단**: 떡 · 공양 · 탕국
- **중단**: 소주 석잔 · 막걸리 석잔 · 점물
- **하단**: (평상시 바닥, 한가위엔 상 위에) 모듬밥 · 모듬탕국 · 막걸리 대접 · 생두부 · 메밀묵
  - 모듬은 초하루 상차림에도 있는 "건립과 그 아래 왕래하시는 조상님들을 위한" 몫.

### 6.5 시간
- 가족이 전안에 모이면 초하루처럼 오전에 차린다.
- 안 모이면 **추석 하루 전 자시(밤 11시)**부터 차릴 수 있다
  (자시 넘으면 다음 날 일진이 되므로 — 제사 기준과 동일).

### 6.6 축원 · 마무리
- 축원: 초하루 축원의 **"초하루맞이 정성"** 부분을 **"한가위맞이 정성 / 추석맞이 정성"**으로 바꾼다.
  이어 조상이 잘 대접받고 갈 수 있게 신령님들께 전안에 고한다.
- **내전(마무리)은 초하루와 동일.**
- 상 내리기: 상차림 후 **1식경(약 2시간)** 지나면 전안 상·차례상은 내릴 수 있다.
  단 건립 상과 그 아래 모듬밥·술은 **추석 당일 늦게** 치운다(늦게 오는 이가 있을 수 있어서).

### 6.7 차례상을 차리는가 / 안 차리는가 (개인 상황)
- 제자 가중에 제사·차례가 **이어지고 있으면** 차례상을 **안 차려도 된다**.
- 제사 격식이 **사라졌거나 안 지내면** **반드시 차린다**.

### 6.8 앱 반영 시 미정 사항
- 6공기·신명 순위(친가/외가/시댁)·"제사 이어지면 생략" 등은 **집집마다 다른 개인 상황**이다.
  앱이 자동 판단하게 할지, 안내 문구로만 보여줄지는 실제 구현 시 결정한다.
- 송편·토란국·차례상 품목·건립 구성은 추석 전용 품목 세트로 데이터화가 필요하다
  (현재 코드엔 추석 전용 품목이 전혀 없음).

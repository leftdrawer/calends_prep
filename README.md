# 은호당 상차림 (calends_prep)

매달 음력 초하루와 명절의 상차림 기록을 관리하는 정적 웹 앱입니다.
초하루는 매달 음력 1일을 기본으로 지내며, 명절은 별도 기록으로 관리합니다.
은호당이 해당 달의 대체를 명시적으로 승인한 경우에만 초하루를 명절로 대신합니다.

## 파일 구조

- `index.html` — 화면 구조와 로그인 입력
- `app.js` — 음력 일정, 가족 암호, 역할별 화면, Supabase 저장
- `styles.css` — 데스크톱·모바일 화면 스타일
- `assets/` — 로고와 홈 화면 아이콘 PNG
- `tests/browser_test.py` — 브라우저 회귀 검사
- `CLAUDE.md` / `DESIGN.md` — 기존 디자인 기준과 외부 참고 자료의 적용 범위
- `.kiro/steering/` — 제품·기술·구조·문서 유지 지침
- `docs/HISTORY.md` / `docs/domain-sangbogi.md` — 변경 이력과 도메인 규칙

별도 빌드나 실행용 패키지 설치가 필요 없습니다. HTML·CSS·JavaScript와 이미지 파일을 함께 배포합니다.

## 붓글씨 PNG 표시

- PC(761px 이상)는 가로 원본 `assets/wordmark-horizontal.png`를 사용합니다.
- 모바일(760px 이하)은 세로 원본 `assets/wordmark-vertical.png`를 사용합니다.
- 로그인·가족 암호 화면과 본문 머리의 세 로고에 동일하게 적용합니다. 이미지를 회전하거나 글자를 다시 만들지 않습니다.
- 모바일 입구 로고는 높이 120–160px, 가족 암호 화면은 120–140px, 본문 머리는 64px로 비율을 유지합니다.
- 두 원본 파일을 모두 읽을 수 있을 때만 자동으로 전환합니다. 하나라도 없으면 기존 `assets/wordmark.png`를 유지합니다.
- 현재 사용자의 두 PNG 첨부는 채팅에서 확인했지만 다운로드 정보가 도구에 전달되지 않아, 실제 두 원본 파일의 저장·적용은 완료하지 못했습니다. ZIP은 필수 형식이 아닙니다.

## 로컬 실행

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저로 로컬 서버의 8000 포트를 열어 확인합니다.

## 사용자별 화면

| 사용자 | 로그인 | 볼 수 있는 것 | 수정 권한 |
|---|---|---|---|
| 은호당 | 기존 여섯 자리 암호 | 전체 준비·예물·기여 기록 | 준비, 날짜, 대체 승인·취소, 체크 초기화 |
| 어머니 | 별도의 네 자리 암호 | 전체 준비·예물·기여 기록 | 준비·예물·완료 체크 |
| 성함으로 들어온 손님 | 이름만 입력 | 보내주신 예물과 지난 차림 기여자 | 보기 전용 |

가족 암호는 브라우저 코드에서 확인할 수 있는 간단한 화면 잠금입니다. 사용자 요청에 따라 이메일 OTP를 제거했습니다.
가족 이름을 손님 이름 칸에 입력해도 암호를 확인합니다. 가족 암호와 로그인 상태는 기기에 저장하지 않습니다.
본문 왼쪽 위 은호당 서명을 누르면 이름 입력 첫 화면으로 돌아갑니다. 준비 기록과 저장 대기 입력은 유지됩니다.

## 기록 호환

데이터는 `app.js`의 기존 `REMOTE` 설정이 가리키는 Supabase `sangbogi` 테이블에 저장합니다.
`REMOTE`에는 브라우저 공개용 anon 키가 있으며 별도 비밀정보가 필요하지 않습니다.

- 기존 `sangbogi:cycle:<연>-<월>` 기록은 모두 초하루 소유로 유지합니다.
- 과거 중양 화면에서 작성한 2026년 9월 기록도 같은 키로 **구월 초하루**에서 이어집니다.
- 명절별 기록은 `sangbogi:event:<연>-<월>:<명절 id>`로 별도 저장합니다.
- 대체 승인은 `sangbogi:calendar:<연>-<월>`에 별도 저장하며 기본값은 승인 없음입니다.
- 중양을 포함해 아직 정하지 않은 명절 상에는 초하루 품목이나 절차를 자동으로 복사하지 않습니다.

상세 규칙은 `docs/domain-sangbogi.md`를 확인하세요. 실데이터를 바꾸는 마이그레이션 SQL은 필요하지 않습니다.

## 초하루 밥공양과 상달 준비

매달 초하루(윤달 포함)에 소당·중당·육당 **밥공양**을 별도로 체크합니다.
각 당 한 공기씩 올리는 기존 안내를 유지하며, 체크하면 해당 진설 자리의 밥공양 표시도 채워집니다.
생쌀 재고와 별개로 기록하고 손님에게는 보이지 않습니다. 구매 수량18개는 장보기 준비만 집계합니다.

정규 음력 10월 초하루에는 가족 화면에 **불사단지 쌀 교체**를 별도 체크 항목으로 표시합니다.
은호당과 어머니가 교체 여부를 체크하며, 작성자·시각과 함께 해당 연도 10월 초하루 기록에 저장합니다.
기존 구매 18개·마무리 6단계와 별개이며, 다른 달·윤10월·성주맞이 등 명절·손님 화면에는 표시하지 않습니다.

`CLAUDE.md`의 적용 범위를 따르며, `DESIGN.md`의 다른 브랜드 색·글꼴로 기존 토큰을 덮어쓰지 않습니다.

## 개발 검증

Python Playwright와 Chromium이 설치된 환경에서 실행합니다.

```sh
python3 tests/browser_test.py
```

테스트는 별도 로컬 서버를 시작하고 Supabase 요청을 모두 테스트 응답으로 처리합니다.
실제 데이터나 이메일 인증 API에 읽기·쓰기 요청을 보내지 않습니다.
가족 암호, 손님 노출 범위, 초하루·명절 분리, 기존 기록 보존, 대체 승인 실패·재시도,
기기 간 날짜·승인 갱신, 저장 실패와 입력 경합, 데스크톱·390px·320px 레이아웃을 검사합니다.
상달 쌀 교체의 월·행사 조건, 어머니의 키보드 체크·저장·새로고침, 연도별 독립 저장과 손님 DOM 제거도 검사합니다.
서명으로 첫 화면 왕복 시 저장 대기 기록 보존과 매달 밥공양의 당별 체크·진설 연동·새로고침·월별 독립 저장도 검사합니다.

클라우드 환경에서 실제 HTTPS 브라우저 검사 시 Chromium NSS 인증서 저장소에 쓰기 접근이 필요할 수 있습니다.
TLS 검증을 끄는 옵션을 사용하지 마세요. 이 환경은 쓰기 접근이 가능한 실행에서 기존 프록시 CA를 사용합니다.

## 배포

GitHub Pages는 `main` 브랜치의 루트를 사용합니다. `.nojekyll`로 정적 파일을 그대로 제공합니다.
코드 수정과 실제 배포는 별도이며, `main`에 푸시한 뒤 GitHub Pages의 배포가 완료되어야 운영 사이트에 반영됩니다.
배포 요청·커밋·확인 결과는 `docs/HISTORY.md`에 기록합니다. 실제 가로·세로 붓글씨 원본 연결은 아직 미완료입니다.
2026-10-11 기능 릴리스 `c1f3f91`의 [GitHub Pages 배포 성공](https://github.com/leftdrawer/calends_prep/actions/runs/38123263147)을 확인했습니다.
현재 운영 버전은 기존 PNG 로고를 사용합니다. 이 클라우드에서는 운영 도메인 접근이403으로 차단되어 실제 운영 브라우저 동작까지 확인한 것은 아닙니다.
클라우드 환경 설정을 저장하거나 게시하는 것도 GitHub Pages 배포와는 별개입니다.

클라우드의 개발 서버는 이 환경 안에서 실행됩니다. 사용자 내장 브라우저에 연결할 미리보기 주소나 포트 전달 기능이 제공되지 않은 상태에서는 서버 정상 실행만으로 화면을 열 수 없습니다. 현재 도구에는 해당 연결 경로가 확인되지 않았습니다.
